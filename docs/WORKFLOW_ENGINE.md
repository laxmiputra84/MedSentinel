# MedSentinel — Dynamic Workflow Engine & DAG Execution

The MedSentinel Workflow Engine powers asynchronous, fault-tolerant execution of complex multi-agent healthcare processes.

---

## 1. Dynamic DAG Construction

Workflows are represented as Directed Acyclic Graphs (DAGs) generated by `PlannerAgent`:
- **Nodes**: Specialized Agent execution steps (e.g., `ocr`, `lab_analysis`, `clinical_rag`, `medication_safety`).
- **Edges**: Data dependencies between steps (e.g., `lab_analysis` depends on `ocr_extraction`).

### Cycle Detection & Validation
Before execution starts, `PlannerAgent.validate_plan()` runs Kahn's algorithm or DFS topological sort to guarantee the graph is completely acyclic. If any circular dependency is detected, planning terminates immediately with a structured error.

---

## 2. Parallel Batch Scheduling

Steps whose dependencies have completed are partitioned into independent parallel tiers. For example:
```
Tier 1: [ocr]
Tier 2: [classification]
Tier 3: [lab_analysis, clinical_rag, verification]  <-- Executed concurrently via asyncio.gather
Tier 4: [safety]
Tier 5: [human_review]
Tier 6: [report_generation]
```
Independent tasks execute simultaneously, drastically reducing end-to-end workflow turnaround time from minutes to seconds.

---

## 3. Persistent Checkpointing & Backend Restart Resilience

To ensure that sudden server restarts or infrastructure failovers do not cause loss of in-flight work:
1. Every step transition creates an atomic MySQL entry in `workflow_steps`.
2. Before and after critical execution phases, a serialized snapshot of `WorkflowState` is written to `workflow_checkpoints`.
3. Upon startup, `WorkflowManager.restore_active_workflows()` queries MySQL for any workflows stuck in `RUNNING` status and re-enqueues them from their latest validated checkpoint.

---

## 4. Failure Recovery & Bounded Exponential Backoff

When an individual agent experiences a transient exception (e.g., downstream microservice timeout):
1. **Retry Mechanism**: The step is retried up to 3 times with exponential backoff (`2^attempt` seconds).
2. **Re-planning Trigger**: If a non-essential step fails permanently, `SupervisorAgent` can invoke `PlannerAgent.replan()` to construct an alternate viable path.
3. **Graceful Escalation**: If a safety-critical step fails, the workflow transitions to `WAITING_FOR_HUMAN` or `FAILED`, alerting the clinical operations team.
